## 0. Execution contract for Codex

Read the design and PRD before changing code. Build the independent library inside Backplane first. Do not begin by replacing the existing LLM proxy or globally renaming `Sigma.Ai`.

This plan elaborates work packages W0–W8 from the supplied design into bounded tasks. It preserves the original T01–T28 acceptance obligations. Proposed file paths are implementation targets, not claims that they already exist. Discover actual host paths, commands, dependencies, and versions during W0.

The first real consumer is Sigma. Backplane WS integration can proceed in parallel after contract freeze. Synapsis and remaining gateway business paths follow the proven consumer pattern. Samgita is not part of this plan.

### 0.1 Non-negotiable rules

1. Pin and inspect source revisions before extracting code. Keep pre-existing failures separate from new failures.
2. Do not modify agent loops, tool executors, context-compression decisions, or Synapsis's agent topology as part of extraction.
3. A production request executes once. No live duplicate calls for shadow comparison and no same-request fallback to the legacy implementation after an uncertain failure.
4. No hidden generation retries, ambient credential fallback, untrusted endpoint selection, or automatic import of Codex credential files.
5. Core cannot depend on TestKit. Keep production dependency and startup trees independent of test servers and Backplane services.
6. Freeze public data/lifecycle/wire semantics before parallel implementation. Contract changes require coordinated updates to all three documents and affected tests.
7. Never report a test, migration, live provider, or release gate passed without actual evidence. Complete unblocked work and report a precise blocker when access or credentials are missing.

### 0.2 Completion record for every task

Record the source SHAs and relevant lockfile identity, changed paths, implemented contract, exact verification command and result, fixture/profile compatibility input, unresolved assumptions, and rollback implications. Use `not_started`, `in_progress`, `passed`, `failed`, `blocked`, or justified `not_applicable` in the acceptance ledger.

A task that implements an interface but leaves required behavior stubbed is not complete. A skipped live test is not a passing live test. Do not use historical Agent Note test totals as current evidence.

## 5. W2 — Implement codecs, framing, and translation rules

**Goal:** One shared bidirectional protocol implementation per declared wire format.

| Task | Output | Dependency / acceptance |

| W2.1 — SSE framing | Bounded byte-incremental framer with complete-frame JSON boundary, newline/UTF-8/multiline/EOF behavior and property tests. | W1.2. T04/T05; test partitions directly, not by assumed TCP chunks. |
| W2.2 — OpenAI Chat codec | Request, non-streaming response, stream and native-error mapping in both directions; independent fixtures. | W1/W2.1. T01/T03/T06/T08 for this codec. |
| W2.3 — OpenAI Responses codec | Same codec surface; ordered output/state/usage preservation and unsupported semantics explicit. | W1/W2.1. T01/T03/T06/T08; do not conflate with Codex profile support. |
| W2.4 — Anthropic Messages codec | Same codec surface, including content/protocol termination distinction and usage/state behavior supported by fixtures. | W1/W2.1. T01/T03/T06/T08. |
| W2.5 — Translation rules | Six directed cross-codec pairs for the common subset, named downgrade handling, runtime incompatibility errors, compatibility matrix. | W2.2–W2.4 plus W1.4. T02/T21; negative tests are required. |
| W2.6 — Usage and observation reducers | Snapshot/delta handling, inclusion relationships, completeness, attempt/observation identity and timing semantics. | W1.2; integrate all codecs. T18; native monitoring integration later. |

Separate ownership of each codec is safe after W1. Shared SSE/usage contracts require one integration owner. Golden samples must include provenance and independently reviewed expected results. Never bulk-accept output snapshots to hide behavior changes.

Cover text, images that need no implicit fetching, parallel function calls/results, role ordering, refusals, output limits, supported structured-output constraints, native state affinity, and rejected vendor features. A codec recognizing an event is not proof that a target can encode it without loss.

**Exit gate:** T01–T06/T08/T18/T21 for the implemented protocol subset. A fixture-driven codec gate makes no live-provider compatibility claim.

**Rollback:** Shared-codec code is still isolated; native production proxy remains unchanged.

## 13. Verification workflow

W0 must record exact commands supported by the pinned repositories. Do not invent project aliases and report them as existing. Every package-changing PR needs formatting, warnings-as-errors compilation, and relevant tests; every protocol change needs golden and property coverage; every transport/auth change needs real-fault and outbound-count coverage.

For independent-consumer verification, use the actual built package payload rather than a sibling path dependency. Record the artifact identity, resolved dependencies, consumer configuration, and commands. Start with no Backplane root config or running service for direct-mode checks. Then run the explicit real-gateway WS test separately.

No default test should require external credentials. Treat live provider access as a separately authorized action with a bounded request/output budget. Source access, toolchain constraints, and missing credentials must be reported precisely. A failed full umbrella test cannot be dismissed as unrelated without identifying the relevant failure and demonstrating scoped new-code results.

Contract changes update the design/PRD/plan, fixture schema or compatibility revision where necessary, and the acceptance ledger together. A report should state what changed, what was tested, what failed or was not run, and which one bounded task is ready next.
