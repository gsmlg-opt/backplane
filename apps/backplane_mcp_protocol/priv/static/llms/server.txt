# Building MCP Servers with Backplane.McpProtocol

This guide shows how to implement Model Context Protocol (MCP) servers using Backplane.McpProtocol. MCP servers extend language model capabilities by providing tools, resources, and prompts.

## Quick Start

### 1. Define Your Server

```elixir
defmodule MyApp.MCPServer do
  use Backplane.McpProtocol.Server,
    name: "my-app",
    version: "1.0.0",
    capabilities: [:tools, :resources, :prompts]
end
```

### 2. Add to Supervision Tree

```elixir
children = [
  Backplane.McpProtocol.Server.Registry,
  {MyApp.MCPServer, transport: :stdio}
]

Supervisor.start_link(children, strategy: :one_for_one)
```

## Protocol Eras

One server module supports both eras. Modern `2026-07-28` Streamable HTTP is
stateless and POST-only; it does not create `Mcp-Session-Id`, GET notification
streams, replay state, or DELETE cleanup. Modern stdio also creates a fresh
frame per request. Legacy peers keep `initialize`, `init/2`, and session state.

Use optional `init_request/2` for request-local modern setup. The validated
request context includes protocol version, client identity and capabilities,
request `_meta`, transport headers, authorization claims, and MRTR inputs.
`server/discover` is provided by the framework.

Modern HTTP validates `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name`, and
safe schema-declared `Mcp-Param-*` mirrors against the body before callback
dispatch.

## Server Components

### Tools - Execute Functions

Tools allow models to perform actions. Create a tool component:

```elixir
defmodule MyApp.Tools.Calculator do
  use Backplane.McpProtocol.Server.Component, type: :tool

  alias Backplane.McpProtocol.Server.Response

  schema do
    field :operation, {:required, {:enum, ["add", "multiply"]}}, type: "string"
    field :a, {:required, {:either, {:integer, :float}}}
    field :b, {:required, {:either, {:integer, :float}}}
  end

  @impl true
  def execute(%{operation: "add", a: a, b: b}, frame) do
    {:reply, Response.text(Response.tool(), a + b), frame}
  end

  def execute(%{operation: "multiply", a: a, b: b}, frame) do
    {:reply, Response.text(Response.tool(), a * b), frame}
  end
end
```

Register in your server:

```elixir
defmodule MyApp.MCPServer do
  use Backplane.McpProtocol.Server,
    name: "my-app",
    version: "1.0.0",
    capabilities: [:tools]
    
  component MyApp.Tools.Calculator
end
```

### Resources - Provide Data

Resources let models read data. Create a resource component:

```elixir
defmodule MyApp.Resources.Config do
  use Backplane.McpProtocol.Server.Component, type: :resource, uri: "config://app/settings", mimeType: "application/json"

  alias Backplane.McpProtocol.Server.Response

  @impl true
  def read("config://app/settings", frame) do
    settings = %{theme: "dark", language: "en"}
    {:reply, Response.json(Response.resource(), settings), frame}
  end
end
```

### Prompts - Reusable Templates

Prompts provide templates with arguments:

```elixir
defmodule MyApp.Prompts.CodeReview do
  use Backplane.McpProtocol.Server.Component, type: :prompt

  alias Backplane.McpProtocol.Server.Response

  schema do
    field :language, {:required, :string}
    field :code, {:required, :string}
    field :focus, {:string, {:default, "general"}}
  end

  @impl true
  def get_messages(args, frame) do
    content = """
    Review this #{args["language"]} code focusing on #{args["focus"]}:
    
    ```#{args["language"]}
    #{args["code"]}
    ```
    """

    {:reply, Response.user_message(Response.prompt(), content), frame}
  end
end
```

## Server Callbacks

Implement callbacks to handle the MCP lifecycle:

```elixir
defmodule MyApp.MCPServer do
  use Backplane.McpProtocol.Server,
    name: "my-app",
    version: "1.0.0"

  # Called after client initialization
  def init(_client_info, frame) do
    frame = Frame.assign(frame, :start_time, DateTime.utc_now())
    {:ok, frame}
  end

  # Handle external OTP processes messages
  def handle_info({:data_update, data}, frame) do
    send_resources_list_changed(frame)
    {:noreply, frame}
  end

  # Handle sampling response (if client supports it)
  def handle_sampling(response, request_id, frame) do
    {:noreply, frame}
  end
end
```

## Advanced Features

### Dynamic Component Registration

Register components at runtime:

```elixir
def init(frame, _params) do
  frame = Frame.register_tool(frame, "dynamic-tool", %{
    description: "A dynamically registered tool",
    input_schema: %{query: : string}
  })

  {:ok, frame}
end

@impl true
def handle_tool_call("dynamic-tool", params, frame) do
  content = "Processed: #{params["query"]}"
  {:reply, Response.text(Response.tool(), content), frame}
end
```

### Server-Initiated Sampling

Request completions from the client:

```elixir
  messages = [
    %{"role" => "user", "content" => %{"type" => "text", "text" => "Hello"}}
  ]

  model_preferences = %{"costPriority" => 1.0, "speedPriority" => 0.1, "hints" => [%{"name" => "claude"}]}
  
  :ok = Backplane.McpProtocol.Server.send_sampling_request(self(), messages,
    model_preferences: model_preferences,
    system_prompt: "You are a helpful assistant",
    max_tokens: 100
  )
```

### Progress Tracking

Report progress for long operations:

```elixir
def handle_tool_call("process", params, frame) do
  token = frame.context.progress_token

  # Send progress updates
  send_progress(token, 0.25, message: "Starting processing...")
  :timer.sleep(1000)
  
  send_progress(token, 0.5, message: "Halfway done...")
  :timer.sleep(1000)
  
  send_progress(token, 1.0, message: "Complete!")
  {:reply, Response.text(Response.tool(), "Processing complete"), frame}
end
```

### Modern Results and Multi-Round Trips

Modern complete results carry `resultType: "complete"`; discovery and
catalog/read responses also expose conservative `ttlMs` and `cacheScope`
hints. `tools/call`, `prompts/get`, and `resources/read` may instead return
`resultType: "input_required"` with input requests and opaque `requestState`.
The client performs roots, sampling, or elicitation work and retries the same
operation. Authenticate or seal state that influences behavior and never log
it.

### Modern Subscriptions

`subscriptions/listen` creates a request-owned HTTP POST/SSE stream or a
multiplexed stdio subscription. Publish JSON-RPC notifications with
`Backplane.McpProtocol.Server.Modern.Subscriptions.publish/2` through the
server's `Backplane.McpProtocol.Server.Registry.subscriptions_name/1` hub.
Closing the request or connection cancels the subscription; modern traffic
does not use the legacy GET stream or session deletion.

### JSON Schema and Tasks

Modern tool schemas preserve arbitrary JSON Schema 2020-12 maps, including
`$defs`, composition, references, and unknown keywords. Peri validates its
supported local subset; external network `$ref` resolution is disabled by
default. `structuredContent` may be any JSON value, including explicit `null`.

The optional modern `io.modelcontextprotocol/tasks` extension is deferred.
Legacy `2025-11-25` Tasks remain available.

### Authorization

OAuth resource-server validation runs before modern dispatch. Request frames
contain normalized authorization claims. The client-side authorization helpers
perform exact RFC 9207 issuer validation; select pre-registration, then Client
ID Metadata Documents, then opt-in DCR; include DCR `application_type`; and
bind persisted credentials to the exact validated issuer.

## Best Practices

1. **Validate All Inputs**: Use schemas to ensure type safety
2. **Handle Errors Gracefully**: Return proper MCP errors
3. **Use Frames Correctly**: Frame assigns are session state on legacy peers and request-local state on modern peers
4. **Log Important Events**: Use structured logging
5. **Test Thoroughly**: Use the test framework for all components
6. **Document Components**: Include descriptions in schemas
7. **Version Your API**: Use semantic versioning

## Example: Complete Server

```elixir
defmodule WeatherMCP.Server do
  use Backplane.McpProtocol.Server,
    name: "weather-mcp",
    version: "1.0.0",
    capabilities: [:tools, :resources]

  component WeatherMCP.Tools.GetWeather
  alias Backplane.McpProtocol.Server.Frame

  def init(_client_info, frame), do: put_api_client(frame)
  def init_request(_request_context, frame), do: put_api_client(frame)

  defp put_api_client(frame),
    do: {:ok, Frame.assign(frame, :weather_api, WeatherAPI.new())}
end

defmodule WeatherMCP.Tools.GetWeather do
  use Backplane.McpProtocol.Server.Component, type: :tool

  alias Backplane.McpProtocol.Server.Response
  alias Backplane.McpProtocol.Server.Error

  schema do
    field :location, {:required, :string}, description: "the unit"
    field :units, {{:enum, ["celsius", "fahrenheit"]}, {:default, "celsius"}}, type: "string"
  end

  def execute(%{location: location} = params, frame) do
    api = frame.assigns.weather_api
    units = Map.get(params, "units", "celsius")
    
    case WeatherAPI.get_current(api, location, units) do
      {:ok, weather} ->
        # sucess resposne
        {:reply, Response.text(Response.tool(), format_weather(weather)), frame}
      {:error, :not_found} ->
        # bussiness logic error
        {:reply, Response.error(Response.tool(), "Location not found"), frame}
      {:error, reason} ->
        # server/protocol error
        {:error, Error.internal_error(reason), frame}
    end
  end
  
  defp format_weather(weather) do
    "#{weather.temp}° - #{weather.description}"
  end
end
```

This architecture provides a clean, extensible way to build MCP servers that integrate seamlessly with language models while maintaining security boundaries and protocol compliance.
