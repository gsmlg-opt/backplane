2. VERIFIED STARTING POINT AND REQUIRED CORRECTIONS

At the review baseline:

A. The Hermes plugin accepts only add/update in on_memory_write and ignores callback metadata. Current Hermes emits add/replace/remove. Its memory-tool patch is normalized to replace, with the complete new entry in content and the complete previous entry in metadata.previous_content. Remove may have empty content.

B. remember already supports request idempotency. Reusing an idempotency key with changed content is an explicit conflict, not an upsert. Host exact-content dedup uses content_hash/scope/memory_type/agent_id and can discard a second occurrence's session/source metadata.

C. The host already persists local memory and outbox atomically and implements retries, restart recovery, canonical ACKs, and dead letters. The plugin's detached daemon threads leave a gap before that durable acceptance and discard delivery results.

D. sync_turn writes truncated user/assistant text directly as episodic memory. This does not create canonical capture events/projected sessions or activate the existing summary/fact extraction pipeline, even when session_id is supplied.

E. Recall V2 and public get exclude expired, deleted, superseded, and archived records. Generic list lacks equivalent lifecycle/expiry filtering, and the plugin injects its results into the system prompt. List responses also omit lifecycle/expiry information.

F. Recall V2 has fusion, deduplication, lifecycle weighting, optional reranking, and token packing. The reviewed vector path lacks an absolute relevance rejection gate. Reranking alone does not remove irrelevant candidates.

G. Current Hermes requires local-only is_available, static system_prompt_block, a useful background-prefetch cache, and on_pre_compress returning reference text rather than mutating conversation messages. Hermes has an optional durable checkpoint API v2.

H. session_id can already persist from host through canonical memory/evidence; the mirror hook fails to send it. Authorized partition isolation exists, but URL agent_id and metadata labels do not automatically isolate profiles.

Treat these as starting observations to verify against current HEAD. Do not describe an existing capability as missing merely because the plugin does not use it.

3. PHASE A: SOURCE IDENTITY, REVISIONS, AND WITHDRAWAL

Define and implement a narrow, versioned external-source mutation contract in the existing memory domain, shared contract package, host facade, and relevant transport. Choose names consistent with the codebase.

Separate:
- Source entry identity: one entry in one provider installation/profile/target, stable across edits.
- Mutation identity: one immutable event, stable across retry and restart.
- Canonical memory identity: the record Backplane serves, which may have several independent sources.

The same native source entry remains the same entry across sessions. Preserve the session provenance of each distinct revision/event without assigning a new entry identity per session. Distinct conversation evidence occurrences remain traceable; retries of the same occurrence do not create additional evidence.

Preserve generic remember's immutable idempotency semantics. Do not overload its idempotency key to mean a mutable source entry.

The contract must represent the operation, source identity, revision or equivalent ordering, immutable event identity, current content when applicable, and actual provenance. Preserve session/parent-session, turn/message references, author/role, target, and repository information when they really exist. Derive authorization from authenticated authority and existing grants; reject caller attempts to inject trusted ownership.

Guarantees:
- Retrying the same event/payload returns a stable result without duplicating source memberships or evidence.
- Reusing the same event key for a different immutable payload fails without partial mutation.
- Reordered or delayed revisions cannot overwrite newer state or resurrect a withdrawn entry.
- Accepted source changes, receipts, and required persistence are atomic, or are coordinated through the existing recoverable outbox.
- Identical canonical content can be deduplicated while every independent source occurrence remains addressable and traceable.
- Fix the mirror path's early content-dedup collision; adding metadata that is then discarded by host dedup is insufficient.
- Source withdrawal removes that source's active contribution and obsolete revision. It must not globally forget independently supported facts.
- When a memory/projection has no remaining valid support, automatic current-context reads must stop treating it as effective.
- Intentional global forget remains a separate operation and retains existing tombstone/derivation protections. Reconciliation must not silently undo it.

Hermes may not expose durable native entry UUIDs. Implement an adapter-owned durable mapping where needed, scoped to installation/profile/target and authorized partition. Use complete previous_content only to resolve an unambiguous existing mapping. Content hashes and old_text search substrings are not source identities. Never use semantic similarity to choose a destructive target.

Several operations in one Hermes batch can share tool_call_id. Do not use tool_call_id alone as an event key. Do not assume an operation index or stable UUID is supplied when it is not. Define durable adapter sequencing and source-state convergence for indistinguishable callbacks. Promise idempotent delivery and deterministic convergence within the actual source contract, not unsupported exactly-once callback interpretation.

Implement source reconciliation for startup, plugin re-enable, missed callbacks, and ambiguous mappings:
- A complete, successfully read source snapshot is required before absence can imply withdrawal.
- Failed, inaccessible, unsupported, or partial reads never mean an empty source.
- Fence snapshot reconciliation against concurrent live mutations.
- Reconciliation is idempotent and scoped to the integration/profile/target.
- Preserve unrelated Backplane memories and explicit global-forget decisions.

4. PHASE B: DURABLE HANDOFF AND DELIVERY STATUS

Replace one-daemon-thread-per-operation with a bounded, tracked delivery mechanism.

Before a callback is treated as successfully captured, its immutable event must be durably retained: either through verified host durable acceptance, or through a narrow local delivery journal that survives host unavailability and process exit. If a plugin journal is needed, keep it limited to delivery/source mapping, not a second canonical memory system.

Reuse existing host outbox/capture upload machinery after acceptance. Preserve event IDs, revisions, timestamps, and all hashed fields across retries. Do not regenerate payloads during replay.

Implement:
- Restart recovery and bounded backoff.
- Defined retryable versus terminal failures.
- Bounded shutdown draining; durability must not depend on shutdown completing.
- Observable local pending, host accepted, canonical committed, and rejected/dead-letter states.
- Stable receipts or status lookup using actual command/event identities.
- Safe handling of lost ACKs and HTTP timeouts after acceptance.
- Explicit failure if local persistence fails; never report durable success in that case.
- Content-safe diagnostics without raw memory, credentials, or full response bodies.

Hermes already tracks background sync work. Ensure the provider's completion semantics reflect durable handoff instead of immediately returning after launching an untracked child thread.

Do not automatically rebind scopes, relabel stored records, or replay commands rejected for authorization/binding errors. Preserve the distinction between provisional local acceptance and canonical success.

5. PHASE C: CONNECT HERMES CONVERSATION EVIDENCE TO THE EXISTING PIPELINE

Add a Hermes adapter to the existing capture/hooks/event-envelope architecture. The reviewed hook map only has claude_code and codex.

Route conversation evidence through existing ingest and session projections so the existing summary, fact extraction, and downstream workers can consume it. Do not keep using one remember(type=episodic) call per turn as a substitute for event capture.

Preserve, where provided:
- Session lifecycle and parent session.
- Stable event/turn/message references and source sequence.
- Separate user and assistant roles, author information, and available tool evidence.
- Repository/source provenance and original record references.
- Input revisions and evidence lineage to resulting memories.

Use actual Hermes messages/context where available. Avoid reingesting the entire growing transcript as new evidence on every turn. Handle retries, overlapping snapshots, resumed sessions, branching, reset, rewind, and on_session_switch without stale session attribution. Explicit memory_save and mirror callbacks must use the correct current session too.

Emit supported session boundaries or integrate with existing incomplete/stale-session handling. An empty on_session_end plus a session_id string is not sufficient.

Replace unmarked user[:500]/assistant[:2000] capture:
- Preserve full evidence within supported limits, or a resolvable original reference.
- For bounded excerpts, preserve truncation status, original length/hash, and source reference.
- Preserve existing privacy/size controls.
- Do not claim complete archival when originals or message classes are omitted.
- Existing truncated data cannot be reconstructed without the original source.

Reuse processing-state, revision guards, job retries, and operator visibility. Demonstrate that a captured Hermes session reaches the existing extraction pipeline and that a derived memory links back to its real input evidence.

6. PHASE D: CURRENT CONTEXT, RELEVANCE, AND TRUST

Define one policy for memory eligible for automatic context. Apply it consistently at the relevant canonical, edge, provisional-overlay, cache, and plugin boundaries.

Exclude deleted, expired, superseded, archived, withdrawn, and explicitly forgotten source contributions as appropriate. Pending updates/deletions must not let older canonical content reappear. Preserve existing authorization-error behavior; do not fall back to local data on an authorization or validation failure.

Audit public current-memory reads separately from explicit historical/operator inventory. Keep history available through an explicit supported path. At minimum, remove dynamic list-based startup injection. If agent-facing list promises current memory, make its visibility semantics match that promise without silently changing unrelated operator history.

Use actual validated API capabilities. At the reviewed baseline, public list does not support project and rejects it; do not invent filters or assume they are silently applied. Recall/get source selectors and metadata are not substitutes for authorization.

Implement configurable relevance rejection that can return zero results for unrelated queries:
- Evaluate real retrieval or reranker relevance, with model/configuration-aware calibration.
- Do not treat rank-fusion final_score as a probability or apply an arbitrary universal cutoff to it.
- Preserve useful lexical/exact matches and define behavior when embedding/reranking is unavailable.
- Keep rejection reasons inspectable without logging sensitive content.
- Reranking must not merely reorder candidates that the relevance policy should reject.

Use the existing token budget/packing machinery. Apply a final budget after canonical/provisional merge and rendering overhead, with deliberate handling of oversized entries. Avoid slicing selected facts at arbitrary character offsets. Deduplicate by real identity/source revision; preserve distinct evidence when content is similar.

Separate raw conversational evidence, candidate inferences, and established facts in automatic use. Do not promote assistant statements to user-confirmed facts merely because they were remembered or have a supporting request row. Preserve truthful provenance and label uncertainty. Integrate this policy with existing evidence/lifecycle mechanisms rather than inventing a second confidence subsystem.

Expose the necessary count, budget, relevance-policy, and source-selection configuration through existing supported configuration surfaces. Preserve clear, truthful provisional/stale/failed indicators.

7. PHASE E: HERMES PROVIDER CONTRACT

Conform to the supported Hermes interface and record its tested version.

- on_memory_write: support add/replace/remove and actual metadata; only support legacy variants with explicit compatibility tests. Remove with empty content must work.
- initialize: bind instance state to hermes_home/profile and supplied context; do not share mutable profile bindings through module globals.
- is_available: local configuration/dependency checks only. Put remote readiness/recovery in initialization or an explicit health flow, without permanently disabling the provider for a transient outage.
- system_prompt_block: static provider instructions only.
- queue_prefetch: populate a bounded cache instead of discarding a remote result.
- prefetch: consume cached, scoped results promptly. Isolate by authorized partition/profile/session/query/policy and appropriate revision/freshness. Invalidate on corrections, withdrawals, scope changes, or revocation.
- on_pre_compress: return reference context via Hermes's supported channel. Never insert fabricated user messages or mutate the caller's transcript. Keep source references.
- shutdown: bounded flush and tracked worker teardown, backed by restart recovery.
- on_session_switch: update session state correctly without changing the profile/authority binding.

Implement the durable pre-compress checkpoint v2 contract for the supported current Hermes baseline, with explicit compatibility behavior for older versions:
- Advertise the capability only after implementing its durability requirement.
- Commit the supplied checkpoint evidence before successful return.
- Raise/report persistence failure so Hermes's checkpoint-required mode can prevent lossy compression.
- Deduplicate repeated/overlapping checkpoint evidence.
- Document that current v2 inputs are direct user/assistant evidence, not the entire tool/system transcript.
- Handle older Hermes versions explicitly without falsely advertising the guarantee.
